# PRD — Release v0.5.0: Multi-Provider AI

- **Status**: Approved (stakeholder-approved in chat; this document formalizes it)
- **Date**: 2026-08-11

## What problem does this release solve?

Every AI step in a workflow today can only ever call Claude — `ClaudeProvider` is the one adapter
the composition root wires up, even though `AIStepConfig.provider` and the Domain `Provider` enum
(`CLAUDE | OPENAI | GEMINI`) already model three providers, and `AIExecutor` already resolves a
provider per step through an injected `AIProviderResolver`. Two concrete gaps block the promise
already implied by the Domain model:

1. **OpenAI and Gemini are stubs.** `packages/ai/openai` and `packages/ai/gemini` both throw
   `Not implemented` — a workflow step configured with `provider: "OPENAI"` or `"GEMINI"` fails
   every run, unconditionally.
2. **A fresh clone with zero API keys cannot demo the AI step succeeding.** `pnpm demo` runs with
   no credentials by design (ADR-0001/README), and today the AI step's failure with no
   `ANTHROPIC_API_KEY` is the expected, "still useful" outcome — but a FAILED demo run undersells
   a product whose entire pitch is AI-driven automation.

This release closes both gaps **without** building any new selection infrastructure — the
existing `AIStepConfig.provider` + `AIExecutor` + `AIProviderResolver` mechanism already does
per-step provider selection correctly (confirmed by an Engine-level test with two AI steps
configured for different providers in one workflow). The only genuinely new piece is a
deterministic `MockAIProvider`, substituted by the composition root — never by the Engine, never
by a workflow definition — whenever a provider's API key is absent at boot.

## Scope: two real adapters, one honest fallback, nothing else

```
OpenAIProvider (real) + GeminiProvider (real) + MockAIProvider (boot-time substitution)
```

- Real `OpenAIProvider` (`packages/ai/openai`) and `GeminiProvider` (`packages/ai/gemini`)
  implementing the exact `AIProvider` port, using the official `openai` and
  `@google/generative-ai` SDKs, following `ClaudeProvider`'s adapter shape and conventions.
- A new `@flowmind/ai-mock` package: `MockAIProvider`, a deterministic, unmistakably-labeled stand-in
  used only inside the composition root when a real provider's key is absent at process boot.
- Composition root wiring: one `AIProviderResolver`, keyed by `Provider`, picking a real adapter or
  `MockAIProvider` per provider based on whether that provider's `*_API_KEY` env var is set.
- Frontend: `OPENAI`/`GEMINI` options added to the AI node's provider dropdown (`apps/web`). No
  `MOCK` option — Mock is never user-selectable.

Anything not listed above is out of scope — see "Explicitly out of scope" below.

## Explicitly out of scope

- **Runtime fallback between providers** (e.g. retry on OpenAI with Claude if OpenAI fails
  mid-run). The Mock substitution is a one-time, boot-time decision based on key presence, not a
  failure-triggered fallback. Automatic runtime fallback is a materially different feature
  (requires defining retry/fallback policy, partial-failure semantics, and probably a new Domain
  concept) and is deferred to a future release if ever pursued.
- **A provider-selection abstraction beyond what already exists.** `AIStepConfig.provider` +
  `AIExecutor`'s injected `AIProviderResolver` already support per-step selection and multiple
  providers coexisting in one workflow; this release adds adapters behind that mechanism, not a
  new one.
- **`MOCK` as a Domain `Provider` value.** A production workflow must never be able to declare
  `provider: "MOCK"` — `AIStepConfig.provider` stays exactly `CLAUDE | OPENAI | GEMINI`. Mock only
  ever appears as a resolver-level implementation detail inside the composition root.
- **Reviving `packages/ai/factory`.** Still a dead stub per ADR-0002's v0.2.2 implementation
  note — out of scope for this release either way.
- **API key configuration UI.** No frontend surface for entering/managing provider API keys —
  keys remain server-side env vars only.
- **Per-provider health-check surfacing beyond what already exists for Anthropic/Slack.**
  `GET /health` is not required to grow `openai`/`gemini` fields this release (nothing in this
  PRD depends on it; a follow-up can add it cheaply if wanted).

## Real risks this release proves

1. **The demo's "no keys required" promise currently degrades to a FAILED AI step.** With
   `MockAIProvider` substituted for `CLAUDE` when `ANTHROPIC_API_KEY` is empty, the seeded demo
   workflow's AI step now succeeds with an obviously-synthetic response instead of failing —
   verified by running `pnpm demo` with all three provider keys empty.
2. **Two SDK integrations (OpenAI, Gemini) must match `AIRequest`/`AIResponse` exactly**,
   including provider-specific quirks: OpenAI accepts a `system` role inline in `messages`
   (unlike Claude, which needs it split out); Gemini needs the same split, plus its own
   `"model"` role name instead of `"assistant"`. Verified with adapter-level unit tests that mock
   each SDK's client, mirroring `ClaudeProvider`'s existing test pattern.
3. **The Mock substitution must never be mistaken for a real model's output** — a demo audience
   or a future engineer reading logs must immediately recognize a Mock response as synthetic.
   `MockAIProvider.complete()` returns content beginning with `[MOCK]` and explicitly stating no
   real provider was configured.

## Non-goals confirmed by reading `ai-executor.ts` and `composition-root.ts` first

- `AIExecutor` already receives `config.provider` per step and calls `this.resolveProvider(...)`
  — no changes needed in `packages/engine`.
- The composition root is already the only place a concrete resolver is built — this release
  extends its resolver from a single `() => claudeProvider` closure to a `Record<Provider,
AIProvider>` lookup, still entirely within `apps/api/src/composition-root.ts`.

## Success criteria

- `OpenAIProvider`/`GeminiProvider` pass unit tests mocking their respective SDKs, matching
  `ClaudeProvider`'s existing test conventions.
- `pnpm demo` reaches a run with the AI step `SUCCEEDED` with zero AI provider keys set.
- A workflow with two AI steps configured for different providers routes each step to its own
  provider (Engine-level test).
- `apps/web`'s AI node dropdown offers Claude, OpenAI, and Gemini — never Mock.
